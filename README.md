## How it works

Every day a GitHub Action runs [`scripts/update.mjs`](scripts/update.mjs). It:

1. Pulls open jobs from the public job board APIs (Greenhouse, Lever, Ashby) of every company in [`config.json`](config.json). No API keys needed.
2. Keeps only internship / new grad roles in software, data/ML/AI, or product/design, located in the US or remote.
3. Merges them with yesterday's list in [`data/listings.json`](data/listings.json): adds new roles, removes ones that were closed, and drops anything older than 120 days. If a company's board can't be reached that day, its roles are kept as they were.
4. Rewrites the tables above and commits the change.

## Add a company

Open a pull request that adds one line to `companies` in [`config.json`](config.json):

```json
{ "name": "Example Co", "ats": "greenhouse", "slug": "exampleco" }
```

To find the `ats` and `slug`, look at the company's careers page links:

| If job links look like… | `ats` | `slug` |
|---|---|---|
| `boards.greenhouse.io/exampleco/...` or `job-boards.greenhouse.io/exampleco/...` | `greenhouse` | `exampleco` |
| `jobs.lever.co/exampleco/...` | `lever` | `exampleco` |
| `jobs.ashbyhq.com/exampleco/...` | `ashby` | `exampleco` |

Run `node scripts/update.mjs --dry-run` to check that the new board loads (failures are printed with a `!`).

## Setup (for maintainers)

Requires Node.js 20 or newer. There are no dependencies to install.

```bash
node scripts/update.mjs --dry-run   # fetch and print counts, change nothing
node scripts/update.mjs             # update data/listings.json and this README
```

**Daily automation.** The workflow lives in [`.github/workflows/update-listings.yml`](.github/workflows/update-listings.yml). It runs once a day (13:00 UTC, about 7–8am Central) and can also be started by hand from the **Actions** tab → **Update listings** → **Run workflow**. For it to push its commits, go to **Settings → Actions → General → Workflow permissions** and choose **Read and write permissions** (only needed if the run fails with a 403 on push). If GitHub ever pauses the schedule (it does this for repos with no activity for 60 days), re-enable it from the Actions tab.

**Tuning** (all in `config.json` → `settings`):

| Setting | What it does |
|---|---|
| `maxAgeDays` | Hide roles posted more than this many days ago (default 120) |
| `newBadgeDays` | How recent a role must be to get 🆕 (default 3) |
| `excludeTitlePatterns` | Regexes; matching titles are skipped (e.g. past seasons like `summer 2026`) |
| `locations` | `us-remote` (default) or `anywhere` |

Which titles count as intern/new grad and which count as SWE, data, or product is decided in [`scripts/classify.mjs`](scripts/classify.mjs).
